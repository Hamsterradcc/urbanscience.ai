# urbanscience.ai

Website of the Urban Science AI Lab. Static site served by GitHub Pages at <https://urbanscience.ai>.

## Site map

| Page | Role |
| --- | --- |
| `index.html` | Identity and agenda: hero, the five research directions, approach, the three platforms, contact |
| `research.html` | The research agenda in full: one section per direction with question, data, and methods |
| `follow.html` | Subscription centre: every feed and calendar, and how to receive them |
| `activity.html` | New discussions and releases from the three sites in one filterable list |
| `digest.html` | The weekly digest, with an archive |
| `404.html` | Not-found page (served by GitHub Pages) |

Shared assets: `assets/site.css` (one stylesheet for every page), `assets/site.js` (mobile navigation, and `?src=example` link handling), `assets/network.js` (view of the network), `assets/activity.js` and `assets/digest.js` (the two list pages), and `assets/follow.js` with `assets/follow.css` (the follow dialog, identical on all four sites). The pages need no build step. The data and feeds are generated by `scripts/build_network.py`.

## Division of labour between the sites

This site holds the lab's agenda and identity only. Outputs are released elsewhere:

- data, indicators, maps, and methods → <https://urbanprobe.com>
- models, agents, and benchmarks → <https://xurbanai.com>
- community and collaboration → <https://citycomputingcollective.com>

## Reserved sections

Sections that are added only when there is something to list, so the site never shows an empty board:

- **Work** — selected outputs, each linking to its platform entry or publication.
- **Teaching** — courses and learning materials.
- **People** — added when the lab has more than one member.

## Network footer and social card

Every page ends with the network footer: the four sites in the same order (Urban Science AI Lab, UrbanProbe, XUrbanAI, City Computing Collective), each with its role, and the current site marked. Keep the order and wording identical across the four repositories.

`assets/og.png` is the 1200×630 card shown when a page is shared; the `<head>` of each page points to it.

## Editing

Pages share the same header, footer, and `<head>` block. When changing them, change every page. Navigation marks the current page with `aria-current="page"`. Direction anchors on `research.html` are `#representation`, `#perception`, `#mobility`, `#climate`, `#agents`; the index links to them.

## Live view of the network

`scripts/build_network.py` reads the public JSON of the City Computing Collective (`data/discussions.json`, `data/taxonomy.json`), XUrbanAI and UrbanProbe (`data/registry.json`, `data/schema.json`) and writes `data/activity.json`. `assets/network.js` reads that file. If it is missing, or with `?src=example`, it builds the same items in the browser from the sites' own files (all served by GitHub Pages with open CORS). `data/network.json` maps each research direction to the shared research themes; the research page shows the discussions and releases in those themes, and the home page shows network-wide counts once there is activity. Without JavaScript or data, the theme-hub links in the HTML still work. Add `?src=example` to preview with the platforms' example data.

The contact section routes visitors by what they need: students to the Collective, collaboration requests to its discussions, data and model contributions to the UrbanProbe and XUrbanAI forms, and everything else to the founder's site.



## Build, outputs and digest rules

`python scripts/build_network.py` (Python 3, no dependencies) runs every six hours in `.github/workflows/network.yml` and commits `data/`, `feeds/` and `sitemap.xml` only when something changed. Options: `--from-dir SITES` reads sibling clones (`SITES/ccc`, `SITES/xurbanai`, `SITES/urbanprobe`) instead of the production URLs; `--examples` reads their `data/examples/` files and needs `--out`, so example items can never overwrite the real files; `--now YYYY-MM-DD` sets the current day; `--out DIR` writes elsewhere. The last three are for local tests only. Characters that XML forbids are removed from all text, and a record without a valid number, id or date is skipped with a warning. Every feed is parsed before anything is written. If a source cannot be loaded, or the data cannot be processed, the script says why and exits 0 without writing. It exits 1 when a research theme is not listed under a direction in `data/network.json`.

| Output | Content |
| --- | --- |
| `data/activity.json` | Newest 200 items, counts for the home page, upcoming deadlines and events. `generated` changes only when the content changes. |
| `feeds/network.xml` | Everything, newest 50 |
| `feeds/theme-<slug>.xml` | One per shared research theme (8) |
| `feeds/direction-<key>.xml` | One per research direction in `data/network.json` (5) |
| `feeds/digest.xml` | One item per weekly digest, newest first |
| `data/digests/YYYY-Www.json`, `data/digests/index.json` | The digests and their list |
| `sitemap.xml` | Pages and digests |

Every item has `id`, `source`, `kind`, `title`, `url`, `date`, `themes`, `label` and `summary`. Output is deterministic for the same input and `--now`.

**Digest rules.** Each run looks at the most recent completed ISO week (Monday to Sunday, UTC). If that week had at least one item and `data/digests/YYYY-Www.json` does not exist, the digest is written. An existing digest is never rewritten, and a week without items gets none. Sections: new discussions by category, questions still waiting for an answer, open calls closing in the next 21 days, events in the next 14 days, new and updated releases.

`data/examples/digests/` holds a digest made from the other sites' example data, shown on `digest.html?src=example`.

## Follow component and newsletter slot

`assets/follow.js` and `assets/follow.css` are the shared follow dialog. Any element with `data-follow` and `data-follow-title` opens it; see the header of `follow.js` for the attributes. The site sets its colours in `assets/site.css` (`--follow-*` variables). `follow.html` lists everything that can be followed, and the bell in the header links to it.

`data/follow.json` holds the owner newsletter slot. Set `provider` to `"buttondown"` and `username` to a Buttondown username to show an email form on triggers marked `data-follow-newsletter="true"` (the weekly digest). With `provider` null the form is hidden.
